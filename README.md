# What's Left in My Fridge 🧊

เว็บช่วยลดขยะอาหาร ใส่ของในตู้เย็นพร้อมวันหมดอายุ แล้วเว็บจะแนะนำเมนูที่ใช้ของใกล้หมดอายุก่อน

ลิงก์ผลงาน: https://whats-left-fridge-icyr.vercel.app

## ปัญหาที่เลือก
หลายครั้งเราลืมของในตู้เย็นจนหมดอายุ หรือมีของเหลืออยู่แต่ไม่รู้จะทำอะไรกิน ทำให้ทิ้งอาหารโดยไม่จำเป็น เว็บนี้จึงช่วยจดของในตู้เย็น เตือนว่าอะไรใกล้หมดอายุ และบอกว่าควรทำเมนูอะไรก่อน

## ฟีเจอร์
- สมัครสมาชิกและเข้าสู่ระบบ แต่ละคนมีตู้เย็นของตัวเอง
- เพิ่มและลบของในตู้เย็น (ชื่อ จำนวน หน่วย วันหมดอายุ) เรียงตามใกล้หมดอายุก่อน ของที่เหลือไม่เกิน 3 วันขึ้นสีแดง
- เมนูแนะนำจากสูตรในฐานข้อมูล ให้คะแนนสูตรที่ใช้ของใกล้หมดอายุสูงกว่า บอกว่ามีวัตถุดิบอะไรแล้วและยังขาดอะไร พร้อมวิธีทำ
- โหมดจับคู่แปลกๆ หยิบของที่ใกล้หมดอายุที่สุดมาจับคู่กับอีกอย่างเพื่อเสนอไอเดียเมนูสร้างสรรค์

## เทคโนโลยีที่ใช้
- หน้าเว็บ: HTML, CSS, JavaScript (ไฟล์ index.html, style.css, app.js)
- ฐานข้อมูลและระบบล็อกอิน: Supabase (Auth, Postgres, Row Level Security)
- เก็บโค้ด: GitHub
- เผยแพร่เว็บ: Vercel (deploy อัตโนมัติทุกครั้งที่ commit)
- ผู้ช่วย AI: Claude,Gemini

## ฐานข้อมูล
- fridge_items: ของในตู้เย็นของผู้ใช้แต่ละคน มี policy ให้เข้าถึงได้เฉพาะเจ้าของข้อมูลที่ล็อกอินแล้ว
- recipes: ชื่อเมนู ประเภทอาหาร และขั้นตอนทำ
- recipe_ingredients: วัตถุดิบของแต่ละสูตร เชื่อมกับ recipes ด้วย recipe_id

## กระบวนการใช้ AI
1. วางแผนก่อนทำ: แบ่งงานเป็นขั้น เริ่มจากทดสอบว่าระบบเชื่อมกันได้ (GitHub, Vercel, Supabase) ด้วยหน้าเว็บเล็กๆ ก่อน แล้วจึงสร้างฟีเจอร์จริงทีละส่วน
2. ทำทีละขั้นและทดสอบทุกขั้น: ให้ AI เขียนโค้ดทีละส่วน (ฟอร์มเพิ่มของ รายการเรียงตามวันหมดอายุ แนะนำเมนู โหมดจับคู่แปลกๆ ตกแต่งหน้าตา) แล้วทดสอบบนเว็บจริงและแคปหน้าจอส่งให้ AI ดูผล
3. ใช้ AI หาสาเหตุเมื่อมีข้อผิดพลาด ตัวอย่างที่เจอจริง
   - ช่องเลือกวันที่ล้นกรอบบน Safari ของ iPad แก้ด้วย CSS
   - ปุ่มเข้าสู่ระบบกดไม่ได้ เพราะไฟล์ app.js มีวงเล็บเกินและโค้ดส่วนท้ายขาด ทำให้สคริปต์ทั้งไฟล์ไม่ทำงาน
   - ฟีเจอร์อ่านรูปขึ้น error ว่าไม่มี API key ทำให้รู้ว่าปัญหาอยู่ฝั่งหลังบ้าน ไม่ใช่โค้ดหน้าเว็บ
4. ตัวอย่าง prompt ที่ใช้ (ปรับให้ตรงกับที่ใช้จริง)
   - 1. เว็บ "What’s Left in My Fridge" (สูตรอาหารจากของเหลือ + ระบบลด Food Waste)
​แนวคิด: ไม่ใช่เว็บแจกสูตรอาหารทั่วไป แต่เน้นการจัดการ "ของตกค้างในตู้เย็น"
​จุดเด่นที่ไม่เหมือนใคร:
​ถ่ายรูป/กรอกวัตถุดิบที่เหลือ: ระบบจะจับคู่สูตรอาหารที่ใช้ของใกล้เน่าก่อน
​แจ้งเตือนวันหมดอายุ: ป้อนรายการของที่ซื้อมา เว็บจะช่วยคำนวณและแจ้งเตือนว่าควรนำอะไรมาปรุงก่อน
​โหมด "จับคู่ของไม่เข้ากัน": แปลงวัตถุดิบแปลกๆ ที่ดูไม่น่าเข้ากันได้ ให้กลายเป็นเมนูสร้างสรรค์
จากข้อมูลที่ให้ไป เธอสามารถสร้างไกด์ไลน์การสร้างเว็บให้ชั้นได้หรือไม่ หากต้องการข้อมูลอะไรเพิ่มเติมถามมาได้เลย
   - 2.Q: อยากใช้เครื่องมืออะไรสร้างเว็บ?
A: Supabase + Vercel + GitHub

Q: ฟีเจอร์ถ่ายรูปวัตถุดิบ ให้ทำแบบไหน?
A: ทำทั้งสองแบบ

## การแบ่งงาน

### หน้าบ้าน (Frontend): อริญรดา ทองแพง
ส่วนที่ผู้ใช้เห็นและกดใช้ ทั้งหมดอยู่ในไฟล์ index.html, style.css และ app.js
- ออกแบบหน้าตาเว็บโทนครัว (สีครีม น้ำตาล เหลืองมัสตาร์ด) และทำให้ใช้งานบนจอมือถือและ iPad ได้
- หน้าสมัครสมาชิก เข้าสู่ระบบ ออกจากระบบ
- ฟอร์มเพิ่มของในตู้เย็น (ชื่อ จำนวน หน่วย วันหมดอายุ) และปุ่มลบ
- รายการของในตู้เย็นเรียงตามใกล้หมดอายุ และขึ้นสีแดงเมื่อเหลือไม่เกิน 3 วัน
- ระบบแนะนำเมนู: ดึงสูตรจากฐานข้อมูลมาจับคู่กับของในตู้เย็น ให้คะแนนสูตรที่ใช้ของใกล้หมดอายุสูงกว่า บอกวัตถุดิบที่มีแล้วและที่ยังขาด และแสดงวิธีทำ
- โหมดจับคู่แปลกๆ และปุ่มสุ่มไอเดียเมนู
- เขียนโค้ดเรียกฐานข้อมูลและระบบล็อกอินของหลังบ้านให้ทำงานร่วมกัน

### หลังบ้าน (Backend): [ชื่อเพื่อน]
ส่วนที่ผู้ใช้ไม่เห็น แต่ทำให้ข้อมูลถูกเก็บและใช้งานได้จริง ทำบน Supabase
- สร้างโปรเจกต์ Supabase และออกแบบตาราง fridge_items, recipes, recipe_ingredients และ ai_usage
- ใส่ข้อมูลสูตรอาหารพร้อมวัตถุดิบและขั้นตอนทำลงฐานข้อมูล
- ตั้งระบบสมาชิก (Authentication) และกฎความปลอดภัย (Row Level Security) ให้ผู้ใช้เห็นและแก้ได้เฉพาะของในตู้เย็นของตัวเอง
- [เติมเอง: เรื่องอื่นที่เพื่อนทำ เช่น ตั้งค่า Vercel และ GitHub ของโปรเจกต์ ถ้าเป็นคนทำ]

### ส่วนที่ทำร่วมกัน
- ตกลงชื่อตารางและชื่อคอลัมน์ให้ตรงกัน เพื่อให้หน้าบ้านดึงข้อมูลได้ถูกช่อง
- ทดสอบระบบรวมกันและแก้ปัญหาที่เจอ เช่น การตั้งค่าอีเมลยืนยันตอนสมัครสมาชิก
- ทดลองทำฟีเจอร์อ่านวัตถุดิบจากรูปถ่ายด้วย AI (หน้าบ้านส่งรูป หลังบ้านเรียก AI) แต่ยังไม่รวมในเวอร์ชันส่ง

### การเชื่อมต่อระหว่างสองฝั่ง
หน้าบ้านเรียกหลังบ้านผ่านไลบรารี Supabase โดยใช้ Project URL และ publishable key ซึ่งเปิดเผยในหน้าเว็บได้อย่างปลอดภัย เพราะสิทธิ์จริงถูกควบคุมด้วยกฎ Row Level Security ที่ฝั่งฐานข้อมูล ส่วนคีย์ลับ (secret key) เก็บไว้ฝั่งหลังบ้านเท่านั้น

## สิ่งที่ยังไม่ได้ทำ / ต่อยอดได้
- อ่านวัตถุดิบจากรูปถ่ายด้วย AI: ทดลองทำแล้วแต่ยังไม่รวมในเวอร์ชันส่ง
- แจ้งเตือนของใกล้หมดอายุ และเพิ่มจำนวนสูตรอาหาร
